# 要件定義書 (Requirements Definition)

## 1. プロジェクト概要
* **プロジェクト名:** Node Plot (`node-plot`)
* **種別:** Visual Studio Code 拡張機能 (Custom Text Editor & Story Plotting Suite)
* **目的:** 小説・シナリオ等の物語制作において、構想やアイデアを「付箋（ノード）」として書き溜め、**名前付き・型付きの複数入出力ソケット（時系列フロー・登場人物・伏線の提示と回収・前提条件）** とパラメータによって構造化・一覧し、`genkou_sheet`（原稿執筆環境）へ直結させるノードベースのプロットツールを提供する。
* **配布・公開形態:** GitHub（オープンソースリポジトリ）および Visual Studio Code Marketplace での一般公開。

---

## 2. コアコンセプトと解決する課題
1. **「付箋の手軽さ」と「本格ノードグラフの構造化（B案）」の融合:**
   * 思いついた段階では単なる「メモ付箋」としてキャンバス上に素早く配置でき、構想が固まるにつれて「シーン」「キャラクター」「伏線」「アイテム・設定」ノードへ昇格させ、複数の名前付きソケットで厳密に因果関係・依存関係を結べる。
2. **物語の破綻（未回収の伏線・キャラの空気化・時系列矛盾）の視覚的検知:**
   * 「どのシーンで張った伏線がどこで回収されるか」「特定のキャラクターがどのシーンに登場するか」「物語全体の感情曲線（テンション）がどう推移するか」をソケット接続とパラメータから自動解析・可視化する。
3. **`genkou_sheet` とのシームレスな連携:**
   * プロットを作って終わりにせず、各シーンノードと実際の原稿ファイル（`.txt` / `.md`）を紐付け、時系列順の構成案出力や `.genkou.json` の原稿順序同期によって執筆工程へ直結させる。
4. **他プロジェクトへの非干渉とデータの永続性:**
   * 実体は人間が読める整形済み UTF-8 JSON（拡張子 `.nplot`）として保存し、通常のプログラミング用ワークスペースには一切干渉しない。

## 3. 機能要件 (Functional Requirements)

### FR-01: 対象フォルダー管理とカスタムエディタ基盤
* **FR-01-1:** `.nplot` ファイルを `CustomTextEditorProvider` によりノードキャンバス画面で開く。裏側のデータは VS Code 標準の `TextDocument` と双方向同期し、Undo/Redo・保存・Git差分管理に対応する。
* **FR-01-2:** コマンド `Node Plot: 新規プロットファイルを作成` または `Node Plot: このフォルダーをプロットプロジェクトとして有効化` により、対象ワークスペースに `.nplot.json` と初期プロットファイルを生成する。
* **FR-01-3:** 有効化されていない通常のワークスペースでは拡張機能はスリープ状態を維持し、標準エディタの挙動を一切変更しない。

### FR-02: 付箋ノードとパラメータ管理
* **FR-02-1 (5種のノード種別):**
  1. **メモ (`note`):** 入出力ソケットを持たない自由付箋（ワンクリックで他種別へ昇格可能）。
  2. **シーン / イベント (`scene`):** 物語の場面・出来事。
  3. **キャラクター (`character`):** 登場人物の定義・目的・属性。
  4. **伏線 / 謎 (`foreshadow`):** 提示と回収を追跡する伏線定義。
  5. **設定 / アイテム (`world_item`):** 舞台設定・重要アイテム・発動条件。
* **FR-02-2 (構造化パラメータ):**
  * 全ノード共通: タイトル、本文（あらすじ・メモ）、カラーラベル、タグ。
  * シーン専用パラメータ: 章・幕（`chapter`）、時系列表記（`timepoint`）、感情・テンション値（`tension`: `-5` 〜 `+5`）、進行ステータス（`idea` / `draft` / `fixed` / `written`）、紐付け原稿ファイルパス（`manuscriptPath`）。
  * カスタムパラメータ: ユーザーが任意の `Key: Value` ペアを自由に追加・編集・削除できる。

### FR-03: マルチソケット入出力（B案）と接続制御
* **FR-03-1 (型付き名前付きソケット):**
  * ソケットは以下の4つのデータ型を持ち、同型（互換性のある型）の入力端子・出力端子間でのみ接続を許可する。
    * `Flow`（時系列・因果フロー：メイン進行および分岐ルート）
    * `Character`（登場人物のシーン参加）
    * `Foreshadow`（伏線の提示 → 回収）
    * `Item`（キーアイテム・設定条件の参照および状態変化出力）
* **FR-03-2 (エッジ表現):**
  * ソケット型に応じたカラーリング、確定ルート（実線）とIF・分岐案（破線）の切り替え、エッジ上の短い関係ラベル表示に対応する。
* **FR-03-3 (カスタムソケット追加):**
  * ノード標準のソケットに加え、ユーザーが任意のラベルと型を指定して入力・出力ソケットを追加できる。

### FR-04: 無限キャンバス・一覧俯瞰・プロット解析機能
* **FR-04-1 (無限キャンバスとフレーム):**
  * パン（ドラッグ移動）、ズーム（縮小時のLOD表示対応）、グリッドスナップ、ミニマップ、および「第1章」「起・承・転・結」などのグループ枠（Frame）による一括移動に対応する。
* **FR-04-2 (関連トレースハイライト):**
  * 特定のキャラクターや伏線、シーンを選択した際、**直接・間接に接続されているノードとワイヤーのみを強調表示**し、他を減光（ディム表示）する。
* **FR-04-3 (アウトライン＆テンション曲線ビュー・伏線チェッカー):**
  * `Flow` 接続をトポロジカルソートした時系列シーン一覧と、`tension` パラメータを折れ線グラフ化した「テンション曲線」、および「提示されたが回収シーンに繋がっていない未回収伏線」の警告一覧を表示する。

### FR-05: `genkou_sheet` 連携・エクスポート・自動バックアップ
* **FR-05-1 (原稿ファイル連携):**
  * シーンノードから対応する原稿ファイル（`.txt` / `.md`）を新規作成またはエディタ（`genkou_sheet` 導入時は原稿用紙エディタ）で直接開く。
* **FR-05-2 (構成案エクスポート & `.genkou.json` 同期):**
  * 時系列順の章立て・シーンあらすじ・登場人物・伏線対応表を Markdown（`.md`）として出力する。また、同一ワークスペース内に `.genkou.json` が存在する場合、シーン順序を原稿ツリーの順序へ反映できる。
* **FR-05-3 (自動バックアップ):**
  * `genkou_sheet` と同様、編集中のプロットを `ExtensionContext.globalStorageUri/backups/` に自動世代管理し、万一のクラッシュや未保存終了から復元できる。

## 4. 非機能要件 (Non-Functional Requirements)
* **NFR-01 (パフォーマンス):** 1ファイルあたり100〜300ノード・500エッジ規模の長編プロットでも、ビューポート外カリングにより60fpsのスムーズなパン・ズーム・ワイヤー描画を維持すること。
* **NFR-02 (データ安全性):** ファイルの実体は標準の UTF-8 JSON（`.nplot`）として保存され、スキーマバージョン管理と不正値サニタイズによりデータ破損を防ぐこと。
* **NFR-03 (セキュリティ):** Webview の Content Security Policy (CSP) を `nonce` ベースで厳格に設定し、外部通信を一切行わずローカル完結で動作すること。
* **NFR-04 (保守性・スタイル一元管理):** UIコンポーネントおよびSVG/Canvas描画における色・サイズ・フォント・余白のハードコードを禁止し、`src/core/theme.ts` と `globalTheme.css` のデザイントークンで一元管理すること。
