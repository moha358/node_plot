# ノードグラフ・ソケット・物語プロット仕様書 (Node Graph & Plot Specification)

## 1. 物語向けマルチソケット設計（B案：型付き名前付きソケット）

各ノード（付箋）は、単なるテキストボックスではなく**「入力ソケット群（左側）」「ヘッダー・本文・パラメータ（中央）」「出力ソケット群（右側）」**を持つ構造化ノードとして機能する。

### 1.1 ソケットデータ型（`SocketDataType`）と接続ルール
ソケットはそれぞれ明確な「意味（型）」を持ち、**同じ `SocketDataType` を持つ Output → Input 間でのみ接続が可能**である（自己接続および同一方向接続は不可）。

| ソケット型 (`SocketDataType`) | 視覚形状・トークン | 意味・用途 | 多重接続（1端子に複数エッジ） |
| :--- | :--- | :--- | :--- |
| **`flow`** (時系列・因果) | ▶ 三角形 (`--nplot-socket-flow`) | 「シーンAの次にシーンBが起きる」という物語の時系列進行・ルート分岐を表す | 入力: 可（合流）<br>出力: 可（IF分岐） |
| **`character`** (登場人物) | ● 丸形 (`--nplot-socket-character`) | キャラクターノードから登場する各シーンへの参加・関与を表す | 入力: 可（複数人登場）<br>出力: 可（複数シーン登場） |
| **`foreshadow`** (伏線・謎) | ◆ 菱形 (`--nplot-socket-foreshadow`) | 伏線の「提示（Plant）」から「回収（Payoff/Resolve）」への対応関係を表す | 入力: 可<br>出力: 可 |
| **`item`** (設定・条件・状態) | ■ 四角形 (`--nplot-socket-item`) | シーン成立に必要なキーアイテム・世界観ルール・前段シーンで得た状態変化を表す | 入力: 可<br>出力: 可 |

---

## 2. ノード種別（5テンプレート）と標準ソケット・パラメータ

初期配置時はソケットを持たない軽量な **`note`（メモ付箋）** として素早くアイデアを書き留められ、ノードヘッダーの種別切替からいつでも以下の構造化ノードへ昇格（変換）できる。また、すべてのノードでユーザーがカスタムソケットを追加できる。

### 2.1 `note`（メモ付箋）
* **用途:** 思いついたセリフ、断片的なアイデア、未整理のメモ。
* **標準ソケット:** なし（ワンクリックで `scene` 等へ変換すると標準ソケットが付与される）。
* **パラメータ:** カラーラベル、タグ、自由 `Key: Value`。

### 2.2 `scene`（シーン / イベント）
* **用途:** 物語の具体的な場面・出来事。プロットの主軸を構成する。
* **標準入力ソケット（左側）:**
  1. `flow_in` (`flow`): 前段シーン
  2. `chars_in` (`character`): 登場キャラクター
  3. `foreshadow_resolve` (`foreshadow`): このシーンで回収する伏線
  4. `condition_in` (`item`): 前提条件・使用アイテム
* **標準出力ソケット（右側）:**
  1. `flow_out` (`flow`): 次段シーン
  2. `foreshadow_plant` (`foreshadow`): このシーンで新たに張る伏線
  3. `state_out` (`item`): 獲得アイテム・状態変化
* **専用パラメータ (`SceneParams`):**
  * `chapter` (string): 章・幕（例：`第1章`, `起`）
  * `timepoint` (string): 作中時間（例：`1日目 朝`, `3年後`）
  * `pov` (string): 視点人物
  * `tension` (number): 感情・盛り上がり度（`-5` 〜 `+5`、デフォルト `0`）
  * `status` (`'idea' | 'draft' | 'fixed' | 'written'`): 進行状態
  * `manuscriptPath` (string): `genkou_sheet` で執筆する原稿ファイルへの相対パス（例：`01_prologue.txt`）

### 2.3 `character`（キャラクター）
* **用途:** 登場人物の定義と、どのシーンに登場するかのハブ。
* **標準入力ソケット:** `relation_in` (`item`: 所属・初期状態)
* **標準出力ソケット:** `appear_out` (`character`: 各シーンの `chars_in` へ接続)
* **専用パラメータ (`CharacterParams`):**
  * `role` (string): 役割（例：`主人公`, `相棒`, `黒幕`）
  * `goal` (string): 目的・動機
  * `flaw` (string): 抱える秘密・弱点・葛藤

### 2.4 `foreshadow`（伏線 / 謎）
* **用途:** 重要な謎や伏線を独立した付箋として明示管理したい場合に使用（シーン同士の `foreshadow_plant` → `foreshadow_resolve` 直結と併用可能）。
* **標準入力ソケット:** `planted_by` (`foreshadow`: 伏線を張ったシーンの `foreshadow_plant` から接続)
* **標準出力ソケット:** `resolved_by` (`foreshadow`: 伏線を回収するシーンの `foreshadow_resolve` へ接続)
* **自動ステータス判定:**
  * `unplanted`: 入力エッジがない（まだどのシーンでも張られていない）
  * `unresolved` (警告表示): 提示シーンはあるが、回収シーンへの出力エッジがない（**未回収の伏線**）
  * `resolved` (完了表示): 提示シーンと回収シーンの双方が接続されている

### 2.5 `world_item`（設定 / キーアイテム / 条件）
* **用途:** 証拠品、鍵となるアイテム、魔法やガジェットの制約、舞台設定。
* **標準入力ソケット:** `acquired_from` (`item`: 入手・発生元シーンの `state_out` から接続)
* **標準出力ソケット:** `used_in` (`item`: 使用先シーンの `condition_in` へ接続)

## 3. プロット解析アルゴリズム仕様 (`plotAnalyzer.ts`)

1. **時系列トポロジカルソート (`computeSceneOrder`):**
   * `scene` ノード間の `flow` エッジ（確定ルート）を有向グラフとして解析し、Kahnのアルゴリズム（同一階層内はキャンバス上の X 座標昇順、次に Y 座標昇順）で時系列順のシーン配列を算出する。
   * 循環参照（ループ）が存在する場合はサイクル箇所を検出し、警告フラグを付与した上で座標順フォールバックを行う。
2. **未回収伏線チェッカー (`detectUnresolvedForeshadows`):**
   * 以下の2パターンを「未回収の伏線」として検出し、サイドバーおよびアウトラインパネルに警告表示する：
     1. `foreshadow` ノードのうち、`resolved_by` 出力エッジが未接続のもの。
     2. `scene` ノードの `foreshadow_plant` ソケットにラベル付き伏線が定義されているが、後続のどのシーンの `foreshadow_resolve` にも接続されていないもの。
3. **関連トレース抽出 (`extractConnectedSubgraph`):**
   * 任意のノード（例：あるキャラクターや伏線）を選択した際、そのノードに直接接続されているエッジと隣接ノード（および `foreshadow` 経由の提示〜回収チェーン）の ID セットを返し、キャンバス上で該当要素のみをハイライト表示する。
4. **テンション曲線算出 (`computeTensionCurve`):**
   * トポロジカルソートされた時系列シーン列から各シーンの `tension`（`-5` 〜 `+5`）を抽出し、物語全体の緩急（起承転結の山と谷）を視覚化する折れ線グラフ用データ列を生成する。

## 4. キャンバス操作・UI インタラクション仕様

* **無限キャンバス操作:**
  * マウスホイール：ズーム（`0.25x` 〜 `2.0x`）。縮小率 `0.5x` 未満では文字潰れを防ぎ俯瞰しやすくするため、ノードタイトルとソケット色のみを大きく表示する **Semantic Zoom (LOD)** を適用する。
  * スペースキー＋ドラッグ（または中ボタンドラッグ / 背景ドラッグ）：パン移動。
  * ダブルクリック：カーソル位置に新規 `note`（または選択中テンプレートのノード）を即座に生成。
* **ソケット接続操作:**
  * ソケット端子からドラッグを開始すると、現在接続可能な互換ソケット端子のみが発光（ハイライト）し、型が異なるソケット端子は減光して誤接続を視覚的に防ぐ。
* **グループフレーム (`PlotFrame`):**
  * 「第1章」「プロローグ」などの背景枠を配置でき、枠内にあるノードをまとめてドラッグ移動できる。
  * 枠の本体（見出し以外）は背景として扱い、枠の上からでもパン・ダブルクリック作成ができる。
* **選択・編集操作:**
  * Shift／⌘クリックで複数選択、Shift＋背景ドラッグで範囲選択。複数選択はまとめて移動・削除・複製・確定度設定・「枠で囲む」が可能。
  * タイトル・枠見出しのダブルクリックでインライン編集（Enter 確定 / Esc 取消、IME 変換中の Enter は無視）。
  * ⌘C / ⌘X / ⌘V（ノードと内部エッジを新しいIDで複製。プレーンテキストはメモ付箋として貼り付け）、⌘D 複製、⌘A 全選択、Esc 選択解除。
  * 出力端子からのドラッグは、入力端子だけでなく**カード上へのドロップ**でも同型の最初の入力端子へ接続する。接続できない場合は理由をトーストで表示する。
  * 種別変更で外れる接続がある場合はトーストで本数と Undo 方法を通知する。
* **ワイヤー表示切替:** 左下の凡例で `flow` / `character` / `foreshadow` / `item` のワイヤーを種類別に表示・非表示できる（Webview 状態として保存）。
* **検索・絞り込み:** 検索語と確定度フィルタに一致しないノードと、それに接続するワイヤーを減光する。検索欄で Enter／Shift+Enter により一致ノードへ順に移動する。

## 5. グループ枠の色・入れ子・リサイズ（ADR-007）

* **色:** `PlotFrame.colorTag` に `none | gray | blue | teal | green | amber | orange | rose | violet` を指定する。実際の色はテーマごとに `--nplot-frame-color-*` で定義し、塗り（`--nplot-frame-fill-strength`）と見出し帯（`--nplot-frame-header-strength`）を `color-mix` で生成する。不正値は読み込み時に除去する。
* **入れ子と所属（保存しない・ジオメトリから導出）:** `src/core/frameLayout.ts`
  * ノードは「アンカー点（左上から 16px 内側）」を含む**最小の枠**に所属する。
  * 枠は「自分を完全に含み、自分より面積の大きい**最小の枠**」を親とする。描画は面積の大きい順（内側の枠が手前）。
  * 枠をドラッグすると、子孫枠とアンカー点が枠内にあるノードがまとめて移動する。ノードを枠外へ出せば所属から外れる。
  * 例：「登場人物」枠の中に「組織A」「組織B」枠を置き、キャラクターを束ねる。インスペクタに所属パス（`登場人物 › 組織A`）、登場表と Markdown 出力に所属グループが反映される。
* **リサイズ:** 枠は 4 辺＋4 角のハンドルでサイズ変更（動かした辺のみグリッドスナップ、最小 160×100）。ノードカードは右端ドラッグで幅を変更（`PlotNode.width`、180〜640px、ダブルクリックで標準幅へ）。
* **枠の操作:** 「選択を枠で囲む」（選択ノードの外接矩形＋余白で新規枠）、「中身に合わせてサイズ調整」、「枠だけ削除」／「中身ごと削除」（2 回クリック確認）。

## 6. 確定度（`PlotNode.certainty`）

* 全ノード共通の任意項目：`decided`（決定・実線）／`proposed`（案・破線）／`unsorted`（未整理・点線＋半透明）。シーンの執筆ステータス（`sceneParams.status`）とは別軸。
* ツールバーの確定度フィルタで絞り込み可能。タグ「決定／確定」「案／仮／候補」「未統合／未整理／保留」から一括設定できる（`applyCertaintyFromTags`）。

## 7. 登場表ビュー（キャラクター × シーン）

* ビュー切替「ノード／登場表／セリフ棚／JSON」。行＝キャラクター（所属枠ごとにグループ化）、列＝時系列順シーン（章ごとの見出し帯付き）。
* セル：`●` 登場、`◎` 登場＋視点人物、`○` 視点人物だが character ワイヤー未接続。クリックで character ワイヤーを付け外し（`toggleCharacterAppearance`）。
* 右端に登場回数・視点回数、下端にシーンごとの登場人数。POV 記述がどのキャラクター名とも一致しないシーンは番号を警告色で示す（`isPovOfCharacter`：括弧書き除去・「／」等で区切った完全一致）。

## 8. セリフ棚（`PlotDocument.lines`, `src/core/lineShelf.ts`, ADR-008）

プロット確定後に、キャラクターが言いそうなセリフを（どのシーンにハマるか未定のまま）書き溜め、物語を駆動させる執筆スタイル向けの機能。

* データ：`PlotLine { id, speakerId, text, note, candidateSceneIds[], placedSceneId? }`。ノードとは別の配列で、キャンバスには描画しない（件数が数百規模になるため）。
  * `speakerId` は character ノード ID（空文字＝話者未定）。`candidateSceneIds` は候補（複数）、`placedSceneId` は確定先（1つ）。確定先は候補に含めない。
  * 状態（未配置／候補あり／確定）は保存せず、**存在するシーン**への参照から導出する（`getLineStatus`）。
  * `lines` を一度も使っていないファイルにはキーを書き出さない（既存ファイルの差分を出さない）。
* 参照の扱い：パース時は参照先の無い ID も保持する（JSON 編集や Undo で失わない）。`removeNodes` でノードを消したときだけ参照を掃除し、配置は外れて棚に戻り、話者を消したセリフは話者未定になる（セリフ自体は消さない）。
* 配置操作：候補追加 `addLineCandidate`、確定 `placeLine`（前の確定先は候補に戻す）、確定取消 `unplaceLine`（候補に戻す）、外す `detachLineFromScene`。
* まとめ入力 `parseLineCaptureText`：新しいセリフとして区切るのは「空行」「話者指定で始まる行」「`「`・`『` で始まる行」だけで、それ以外の改行はセリフ内の改行として残す（入力欄の Shift+Enter で複数行のセリフを書けるように）。`@名前 本文`（未登録名は話者未定＋メモに表記を残す）、`名前「本文」`・`名前：本文`（名前が既存キャラに一致する場合のみ話者扱い）、話者指定なしの行は直前の話者を引き継ぐ。末尾の `// メモ`、鉤括弧の後ろの `（メモ）` はメモ欄へ。名前照合は `findCharacterByName`（肩書き・括弧除去後の完全一致を優先、一意な部分一致も可）。
* セリフ棚ビュー（`LineShelfView.ts`）：左＝話者ごとの列（キャンバスの読み順、最後に話者未定）、右＝時系列順のシーン一覧（ドロップ先、`★確定 ☆候補` の件数）。シーンのクリックでそのシーンのセリフに絞り込み、その間に書き留めたセリフはそのシーンの候補になる。入力欄は再描画で作り直さない（入力中の文字とフォーカスを保つ）。
* 並び順：`doc.lines` の配列順がそのまま列内の順・会話順。カードを別のカードの上半分／下半分へドロップでその前／後ろへ移す（`moveLine`）。話者列の別キャラのカードへ落とすと話者も変わる。シーンで絞り込むと話者混在の 1 列（会話順）で表示し、同じ操作で会話の順番を入れ替える。
* キャンバス：シーン／キャラクターカードに `💬` 件数チップ。インスペクタでシーンのセリフの確定・解除、キャラクターのセリフの追加。
* ホストコマンド `nodePlot.captureLine`：話者 QuickPick → InputBox の連続入力。直近に開いていたプロットが対象（無ければ開いている／ワークスペースの `.nplot` から選択）。アクティブエディタの原稿が `manuscriptPath` に一致するシーン（`findSceneByManuscriptFile`）があれば候補として付ける。どのエディタにも表示されていないプロットは追加後に保存する。
